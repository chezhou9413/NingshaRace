# 蚁群近战能力与伤残检查

## 日志与原因

报错中的 `bodyVerbs` 只有 `HeadClaw/.../Slash`，而 `verbList` 为空：兵蚁有配置的头爪招式，但在当时已经没有通过原版可用性检查的近战招式，蚁群却仍派发了 `AttackMelee`。

兵蚁和蚁后原配置只有头爪攻击。原版 `BeetleLikeWithClaw` 确实包含 `HeadClaw`，因此不是引用不存在的身体组。原版 `Verb.IsStillUsableBy()` 会根据招式可用性、所有者及伤害系数过滤；头爪缺失、身体部位效率归零等情况可以使唯一攻击失效。堆栈不包含伤情，不能仅凭日志确认该个体具体缺失了哪个部位。

原版巨型蜘蛛与洞穴昆虫的攻击表还包含 `HeadAttackTool` 头撞备用攻击；该身体组在两种甲虫身体中均存在。目标是机械体并不是空攻击列表本身的证据，不修改敌我识别或机械体的受伤规则。

## 实现

- 兵蚁、蚁后、工蚁、爆浆蚁、吐酸蚁补充低伤害头撞，伤害分别为 4、5、2、1、3，冷却 2 秒，`chanceFactor=0.1`。
- 备用攻击使用原版 `HeadAttackTool` 和 `ensureLinkedBodyPartsGroupAlwaysUsable` 规则；主攻击的身体组、伤害、冷却和伤残判定不改变。不恢复伤势，不让断掉的头爪继续造成原伤害。
- `Combat/AntMeleeCapability.cs` 同步读取原版当前可用近战列表，并检查针对目标的正选择权重；不调用会因空列表报错的选招方法，不保留原版共享临时列表。
- `Jobs/JobDriver_DesertPitAntMelee.cs` 继承原版近战驱动器。保留寻路、命中、攻击次数和结束逻辑，在全局失败条件及 `AddPreTickIntervalAction` 中检查攻击能力。
- 原版 `DriverTickInterval` 不执行全局失败条件，近战出手却在间隔更新中发生，因此不能只添加 `FailOn`。
- 巢群近战使用独立 `NingshaRace_Job_DesertPitAntMelee`。无法近战时不创建攻击任务，转回巢穴工作；已经执行的专用任务若失去攻击能力则结束。
- 爆浆蚁自爆、吐酸蚁远程弹丸、调查队和蚁狮的独立任务规则不改动。不使用全局死亡或近战 Harmony 补丁，不吞异常、不屏蔽日志。

## 验证与边界

已经完成 Release 编译、XML 静态解析、身体组及源码 API 核对和 `git diff --check`。保留既有 MSB3270 架构警告。没有启动游戏或运行战斗测试，尚未部署、提交或推送。

不迁移已经保存的原版 `AttackMelee` 任务；更新后由正常任务结束及重新派发流程切换到专用任务。备用攻击由种族定义加载，不需要重建洞穴地形。

人工验收（未执行）：

1. 健康兵蚁近战攻击人类、动物与机械体，主攻击强度保持原配置。
2. 头爪缺失的兵蚁和蚁后能使用低伤害头撞，而非重复报空攻击列表。
3. 工蚁、吐酸蚁和爆浆蚁口器受损时，通用近战仍有备用招式；爆浆蚁自爆逻辑不改变。
4. 追击途中或贴身战斗期间失去全部可用近战能力，专用任务在攻击回调前退出，并不立即反复派发同一无效任务。
5. 读档后继续战斗，目标倒地、死亡、离图及破门寻路由原版任务处理；若仍报错，保留第一条完整堆栈、当时伤情和相关战斗模组列表。
