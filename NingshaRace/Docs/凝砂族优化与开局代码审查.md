# 凝砂族优化与开局代码审查

审查日期：2026-09-05。范围：八项优化、祭坛救援任务和“深砂遗民”开局。依据为项目源码及本机 RimWorld 1.6 原版源码；未启动游戏。

## 已处理问题

| 优先级 | 问题 | 原因与处理 |
| --- | --- | --- |
| P1 | 救援阵营加载红字 | 人形 `FactionDef` 必须有背景过滤器；PawnKind 的配置不能替代阵营配置。为 `NingshaRace_RescueFaction` 添加 `NingshaRace` 背景分类，保留人形阵营属性。 |
| P1 | 地下任务地图岩顶被清空 | `GenStep_DesertPitTerrain` 改为读取生成器 `roofDef`，蚁巢和地下救援生成器却未配置该字段。补上 `RoofRockThick`，保持两种任务原有的天然厚岩顶规则。 |
| P1 | 备用开局人物缺少种族异种 | 原版只替最初三名必选人物清空强制基础人异种；后五名使用默认请求生成。专用 `ScenPart_NingshaStartingPawns` 为备用人物建立索引化生成请求，清除 `ForcedXenotype`，使种族异种表生效；重随机、候选人排序和场景编辑副本保留对应路径。 |
| P1 | 开局看不到成员 | 用户现有日志记录三名成员均发生 `DropThingsNear failed`。原版 Standing 仍先寻找空投落点，厚岩顶导致失败并改投随机格。专用安置流程直接生成在离洞绳附近，限制连通范围、揭雾并定位镜头。 |
| P1 | 开局没有上行出口且生态仍来自地表 | 旧方案把洞穴生成器挂在地表聚落上，没有配对入口，因此出口步骤跳过生成，生态也仍读取地表格。现在先生成沙漠地表，再在非嵌套阶段创建真正的地下家园并双向绑定出入口。 |
| P2 | 背景混入原版故事 | 原版将 PawnKind 普通过滤器与玩家派系过滤器合并抽取。殖民者改用 `backstoryFiltersOverride`，且移除旧的 `backstoryCategories`，只抽凝砂族故事。 |
| P1 | 救援任务可能在生成目标时中断 | 原代码只在四个固定角落半径十格内抽样，洞穴拓扑不保证角落有空地；地表山体也可能封闭该区域。现在一次收集真实可站立空地，再按四角方向选择与待救者连通的格子，保留距玩家入口至少二十格、目标不重叠和数量三倍的规则。无满足条件的格子仍明确报错，不吞异常。 |
| P2 | 部分岩块未接入拆除回收 | 原先只替换地形步骤，`GenStep_DesertPitScatter` 和 `GenStep_DesertPitLandmarks` 仍生成原版砂岩块及塌落岩。现已统一使用专用小碎石和大塌岩。纯坠砂发射器和岩屑污迹不参加回收。 |
| P2 | 拒绝按钮与任务时间信息有重叠路径 | 原版在接受按钮之前的纵坐标绘制右对齐时间信息；原补丁只避让其他按钮，没有避让这块区域。仅对当前未接受的祭坛任务，将时间信息放在完整按钮区域之后。普通任务保持原样。 |

## 技术入口与原版依据

- 阵营：`1.6/Defs/AltarMissions/NingshaRace_RescueFaction.xml`。原版 `FactionDef.PostLoad` 把 `backstoryCategories` 转换为 `backstoryFilters`；`FactionDef.ConfigErrors` 单独检查人形阵营的过滤器。
- 岩顶：`1.6/Defs/AltarMissions/NingshaRace_AltarMissionSites.xml`。原版 `MapGenerator.GenerateMap` 的地下预铺阶段允许空值回落到厚岩顶，但自定义地形步骤随后的 `SetRoof(cell, roofDef)` 会覆盖结果，不能依赖预铺阶段。
- 开局：`Scenarios/Parts/ScenPart_NingshaStartingPawns.cs` 与 `Defs/Scenarios`。原版 `StartingPawnUtility.DefaultStartingPawnRequest` 强制 `Baseliner`；`PawnGenerator` 优先使用 `ForcedXenotype`，再考虑种类异种表。原版候选人拖动同步重排请求；本实现保留每人的索引请求。
- 救援选点：`AltarMissions/Map/AltarRescuePlacementUtility.cs`。使用原版 `Reachability.CanReach` 与 `TraverseMode.PassDoors`，寻路及实体生成不并发执行；不通过挖空岩层制造出生位置。
- 岩块：`DesertPit/Generation/Steps/GenStep_DesertPitScatter.cs`、`GenStep_DesertPitLandmarks.cs`。使用已有 `CompDesertPitSalvage`；未调整回收权重或材料数量。
- 任务 UI：`AltarMissions/UI/Patch_MainTabWindow_Quests_AltarInfoLayout.cs`。原版 `DoQuestInfo` 在 `DoAcceptButton` 后调用 `DoRightAlignedInfo`，后者仍接收旧的 `curYBeforeAcceptButton`。布局补丁只调整参数，不改变全局绘制状态。

## 仍需明确的开局限制

### 世界必须存在可用沙漠

`ScenPart_ForcedDesertPitStart` 只从原版 `Desert` 且允许建立殖民地的世界格中抽选。不包含极端沙漠；极端温度、降雨或世界覆盖参数可能让候选集为空，此时当前实现明确抛错。它保证“选中时一定是沙漠”，不保证“任意世界参数都一定能开局”。本次未擅自改变世界生成参数、转化世界地貌或加入自动重建世界流程。

### 地表与地下使用两张相连地图

`ScenPart_ForcedDesertPitStart` 选择沙漠并用 `Base_Player` 生成地表。`ScenPart_NingshaUndergroundArrival.PostGameStart` 在原版地表生成与初始化全部结束后创建地下家园，避开 `MapGenerator` 静态临时网格不可重入的问题。地下使用 `NingshaRace_DesertPitStartingMap` 的口袋地图生态与24℃基础室外温度，不追加地表地貌变体。

`NingshaRace_DesertPitHome` 使用 `PocketMapParent`，在生成前指定玩家阵营、家园属性和对应沙漠世界格。地表入口与地下离洞绳双向绑定并沿用原版引用存档；地下人物和物资在地图生成后直接安置，不再执行 `ScenParts` 空投步骤。具体入口、失败条件与手工验收见 [深砂遗民开局修复说明](深砂遗民开局修复说明.md)。不转换旧开局地图或已有背景；商队、世界格变体组合及完整生态循环仍待运行时验收。

## 已检查但未发现明确错误的路径

- 拒绝任务使用 `InvalidPreAcceptance`，仅匹配登记任务；未接受任务的原版隐藏会释放槽位，已接受任务隐藏不释放，不退款。
- 沙傀到期 tick 被序列化，稳定阶段递减并转入既有消散流程；两个进度面板按字体行高布局并恢复绘制状态。
- 回收仅在拆除模式选择一种奖励，权重为 50、25、15、10；战斗摧毁、消失和开发者删除不触发这份奖励。
- 侵蚀体掉落走 Mutant 遗留物流程，不增加全体凝砂族死亡掉落补丁。
- 开局装备阶段前，原版 `GameInitData.PrepForMapGen` 已移走未选候选人，因此装备组件使用三人列表并非八人列表错误。

以上是源码结论，不等于游戏运行时通过；尤其不能用编译证明 Harmony 注入、Def 加载和新世界生成全部正常。

## 验证与维护边界

- 验证仅执行 Release 编译、XML 严格解析与静态差异检查，不启动 RimWorld。
- 保留既有 HarmonyMod AMD64 与项目 MSIL 的 MSB3270 警告；本次不改依赖架构。
- 人工验收补充在洞穴开局、祭坛与蜕皮测试须知中，状态均为待手工。
- 不迁移旧存档中的旧岩块、错误候选人或已生成的无顶任务地图。
- 蛇腹剑别名、任务难度和蚂蚁食物能力不属于本次处理范围。
