# 深砂遗民开局修复说明

## 故障依据

- 用户本机 `Player.log` 记录 Alex、Velasquez、Murillo 三名开局成员的 `DropThingsNear failed`。原版 `ScenPart_PlayerPawnsArriveMethod` 的 Standing 仍调用 `DropPodUtility.DropThingGroupsNear`，先通过厚岩顶受限的空投选点，再决定直接放置；直接放置不代表跳过空投选点。
- `PawnBioAndNameGenerator.GetBackstoryCategoryFiltersFor` 将 PawnKind 的普通过滤器和派系过滤器合并，因此仅配置 `backstoryCategories=NingshaRace` 不能排除原版玩家派系背景。
- 原开局在地表聚落上直接生成洞穴地形，没有 `currentlyGeneratingPortal`，出口步骤不会创建离洞绳。未启用 `isPocketMap` 时，地图生态与季节温度仍来自地表世界格。
- 2026-09-07 的 `Player.log` 首个开局异常为 `ScenPart_StartingAnimal.PetWeight` 空引用。原版 `Scenario.AllParts` 先列出玩家派系部件，其 `PostGameStart` 清空 `GameInitData.playerFaction`；之后才执行地下安置，因此在此时枚举随机动物生成器会读取已清空的派系。后续 `MapDrawer.Dispose`、迷雾、沙地和积雪图层异常是失败清理期间的连锁报错，不是菌子补生或图形清理前置补丁触发的首个异常。

## 最终流程与职责

1. 自动选择原版沙漠世界格，禁止手动选址；地表使用 `Base_Player`。
2. 地表的原版 `ScenParts` 步骤调用专用部件的 `GenerateIntoMap`，完整生成场景物资、个人物品和随机家养动物，仅暂存在本次开局的实体清单内，不投放地表。原版完成地表生成、初始化与镜头准备后，专用场景部件在 `PostGameStart` 创建地下地图；不在 `GenerateIntoMap` 或 `PostMapGenerate` 中嵌套地图生成。
3. 地表巨坑入口检查完整8×8占地、两格外圈、无岩顶和通往地图边缘的道路，不覆盖已有建筑或人物。
4. 地下使用完整巨坑生成步骤、专用生态、稳定厚岩顶和24℃基础室外温度。地下尺寸沿用开局地图尺寸；普通探索巨坑为200格配置。当前分层洞群、水系和采收规则见 [基因洞群与生态掉落调整](基因洞群与生态掉落调整.md)。
5. 地下父对象在生成前设为玩家家园，和地表入口、离洞绳建立可存档的双向连接。
6. 地图完成后，清理离洞绳六格内的阻挡物，保留绳索、生物和物资，核对实际可达性。直接安置三名已选成员，按合法单堆上限放置已准备的物资和动物，不在此时重新枚举 `PlayerStartingThings()`。
7. 揭开安置区迷雾、设置家园区并将初始镜头移到成员身边；普通巨坑不触发这个一次性开局部件。

源代码均相对 `1.6/Source/NingshaRaceLib`：

| 入口 | 职责 |
| --- | --- |
| `Scenarios/Parts/ScenPart_ForcedDesertPitStart.cs` | 固定沙漠世界格与地表生成器 |
| `Scenarios/Parts/ScenPart_NingshaUndergroundArrival.cs` | 管理本次开局的临时物资清单，分别调度地表准备与地下安置 |
| `Scenarios/Generation/NingshaStartingSupplies.cs` | 在临时派系有效时完整生成场景与个人物资，包括原版随机家养动物 |
| `Scenarios/Generation/NingshaDesertPitStartUtility.cs` | 地下家园创建、入口绑定与镜头 |
| `Scenarios/Generation/NingshaStartingGatePlacement.cs` | 地表入口占地与通行检查 |
| `Scenarios/Generation/NingshaStartingPartyPlacement.cs` | 安置区整理、人物与物资直接落地 |

定义位于 `Defs/Scenarios`、`Defs/DesertPit/MapGeneration/Maps` 与 `Defs/Race/PawnKinds/PawnKind_NingshaRace_Colonist.xml`。开局人物种类 `NingshaRace_DesertPitStarter` 从凝砂殖民者继承基因和 `backstoryFiltersOverride`，不同时保留普通过滤器，避免原版配置冲突。八名候选人、重新随机及候选人排序均使用专用开局种类，不改动其他场景的凝砂殖民者。

## 开局科技、物资与防护

玩家派系 `NingshaRace_DesertPitPlayerFaction` 仅由本场景的 `scenario/playerFaction/factionDef` 引用，科技等级为中世纪。初始研究采用原版部落的 `TribalStart`，科技蓝图采用 `TribalStart` 和 `TribalStartTechprints`，不沿用工业开局的 `ClassicStart`。派系科技等级决定原版科技层级规则，不自动完成所有中世纪研究，也不锁死后续研究。派系背景类别仍为凝砂族，避免原版人形派系配置检查报错。

物资依据本机原版 `Defs/Core/Scenarios/Scenarios_Classic.xml` 中的 `LostTribe`，只取物资、武器和三只动物，不复制五人数量、营养不良或饥饿开场。

| 内容 | 数量与放置方式 |
| --- | --- |
| 干肉饼、草药、木材、白银 | 400、20、500、200，直接放在地下安全区 |
| 木棒、钢制短矛、短弓 | 各一件普通品质，按三人顺序直接装备 |
| 玉制小刀、短弓、投矛 | 各一件普通品质，放在地下；与随身武器合计为原版部落六件武器 |
| 家养动物 | 三只，种类、驯养和羁绊条件沿用原版部落，在地下出生 |
| 服装 | 每人普通品质凝砂裹胸布与凝砂短裤，沿用原有贴图和属性；单件利器、钝器防护均为1%，热防护2% |

开局人物不抽取完整套装、作战内衬或高阶战术斗篷，随机科技植入物概率为零。不削弱这些服装本体，也不改变非开局凝砂殖民者。包装生存食品、工业药物、零部件、散装钢铁、砂岩砖及种族专属武器不作为场景赠品；地图自然资源和人物自带物品不在这份固定清单内。

原版部落的木材使用 `ScenPart_ScatterThingsNearPlayerStart`，这里使用 `ScenPart_StartingThing_Defined` 交给地下安置逻辑，避免500木材落在地表。`ScenPart_StartingAnimal.PlayerStartingThings()` 在地表场景生成阶段被完整枚举，生成的动物稍后走同一地下安置入口；仅保存 `IEnumerable` 而不枚举无法提前生成动物。临时清单不序列化，成功安置后释放引用，后续探索地图和读档不重建该清单。`Scenarios/Equipment/NingshaStartingWeapon.cs` 保存武器与材料，`ScenPart_NingshaStartingEquipment` 深度序列化配置、校验材料并使用 `ThingMaker.MakeThing(weaponDef, stuff)` 生成，避免木棒或短矛缺少材料。

## 图标加载的线程边界

地下开局的 `PostGameStart` 随原版 `Game.InitNewGame` 在长事件后台线程执行。`NingshaStartingGatePlacement.Spawn` 创建入口时，`ThingWithComps.InitializeComps` 首次实例化 `Comp_NingshaPortalCargo`，会触发该类型的静态字段初始化。若此时调用 `ContentFinder<Texture2D>.Get("UI/Commands/LoadTransporter")`，原版会输出跨线程资源错误并返回 `null`；静态只读字段随后持续保存空值，因此仅重新选择入口不能恢复图标。

`Comp_NingshaPortalCargo` 使用原版 `[StaticConstructorOnStartup]`，由 `PlayDataLoader` 在加载结束后的主线程阶段调用 `StaticConstructorOnStartupUtility.CallAll` 预加载图标。原版 `CompTransporter` 使用相同机制和资源路径。入口创建只复用完成初始化的类型，不把地图生成整体搬到界面线程，不在组件构造时排队回调，也不屏蔽资源错误。

同类静态资源入口已核对：`UI/Gizmos/NingshaCommandIcon` 同样标记启动预加载；`CompNingshaMolting` 已有该标记。命令图标的裁切、绘制尺寸、颜色状态与业务交互不变。本次扫描针对静态初始化中的资源加载，不代表所有渲染路径都经过运行时线程验证。

交付需要同步 `1.6/Assemblies/NingshaRaceLib.dll` 并完整重启 RimWorld，使启动预加载重新执行。此问题不需要修改贴图、重建 Shader 包或迁移存档；只重新载入存档不能清除当前进程中的静态空图标缓存。

## 边界与验收

生成和安置串行执行，不在并行扫描中修改地图。地图生成入口状态用 `finally` 清理，不吞掉缺失出口、放置失败等错误，也不修改人物渲染来掩盖落点错误。

只完成 Release 编译和 XML/源码静态核对，不启动游戏。运行时检查见《凝砂族1.0洞穴开局测试须知》START-01 至 START-08，重点是三人可见、种族背景、离洞绳可达、上下往返、部落物资数量、基础装备、中世纪科技、驱蚁桩及读档引用。

不迁移旧存档、旧自定义场景副本或已存在人物的背景。更新模组后，应从模组自带“深砂遗民”重新开局。地表与地下为两张地图，并非新的地下世界层；从地表组织商队，地下房间仍受热源和温度交换影响。
