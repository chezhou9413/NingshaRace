# 巨型墓葬生成说明

## 功能入口

每张新生成的沙漠巨坑固定放置一个 `NingshaRace_GiantTombBrokenCoffin`。它使用现有封闭砂岩石棺外观，但不会生成尸体或普通石棺奖励。玩家控制、清醒且具有视力的殖民者在视线可达的 8 格内首次发现它时会收到一次提示；右键下达“调查破损砂岩石棺”后，殖民者会在石棺旁调查 300 Tick，并将它原地开启为 `NingshaRace_GiantTombCoffinEntrance`。

殖民者首次通过开启石棺入口进入时，框架会建立一张 200×200 的原版口袋地图，并显示分帧生成进度。入口、返回出口、`PocketMapParent` 和世界口袋地图登记都沿用原版机制。旧的独立 8×8 `NingshaRace_GiantTombGate` 已经删除，不再生成或提供开发者放置入口。

本功能需要：

- ChezhouLib
- Royalty
- Ideology
- 凝砂族原有的 Biotech 与 Anomaly 依赖

ChezhouLib 已自行启用 `ClCustomMission`，凝砂族不重复声明该门控。

## 模板数据

运行时模板位于：

`1.6/Data/CustomMission/MapTemplates/GiantTomb`

每个模块必须同时包含：

- `.clmap`：ChezhouLib 二进制地图模板。
- `.clmeta.json`：metadata v2、二维结构网格和推断连接点。
- `.preview.png`：作者定位结构使用的缩略图，不参与运行时生成。

当前配置固定使用 19 种模板，每种至少出现一次，每张地图再随机增加 24–32 个实例。额外实例按接口守恒分类抽取：约 20% 为四接口中转节点，每个中转节点配两个尽头走廊或小房间；余下二接口模块约四分之三使用中转房间，只有约四分之一使用普通走廊。生成结果因此以可探索房间和支路终点为主，同时保证所有接口闭合。

更新模板时，需要把三个同名文件一起覆盖到上述目录，并确认 XML 中 `ClMapTemplateDef.dataPath` 仍指向对应 `.clmap`。运行时会严格核对 schema、版本、文件名、二进制大小、格网尺寸和连接点，错误不会静默回退。

## 拼接规则

`带尽头走廊`固定作为南部入口，唯一接口朝北。其余模块允许四向旋转和 X 轴镜像，最终形成一棵使用全部接口的连通树。

接口兼容关系：

- 同宽门连接同宽门。
- 同宽开放口连接同宽开放口。
- 双宽门可连接双宽开放口。
- 单门可居中连接三宽开放口。

模块矩形不能重叠。除正在连接的父子模块外，任意两个模块之间至少保留一格天然岩层。门对门时只保留父模块一侧的门，避免连续两格门；开放口直接相邻。

布局求解在主线程按模板许可的旋转、镜像组合准备一份共享几何目录。每个出口缓存固定的候选坐标和矩形；搜索向前推进时只检查此后加入的房间，撤销房间时精确恢复它阻挡的候选。递归仍优先选择真实可摆放候选最少的出口，选中后直接复用已检查的候选，不再重复进行几何计算。成功后日志记录已完成尝试数、摆放候选数、矩形碰撞检查数和搜索耗时。

模板池建立后还会分别统计单门/三宽开放口与双门/双宽开放口等兼容组。任何兼容组出现奇数接口时都会在空间搜索前重新抽取，因为这种组合不可能让全部接口两两闭合。终点大墓室按支路纵深加权放置，不会被强制拖到空间已经被小模块占满的最后阶段。

空间布局使用后台并行搜索。正常阶段使用最多 8 个尝试，共享 500000 次候选摆放预算。后台按 CPU 数量并行并保留一个核心供游戏界面使用，最多同时使用 8 个工作线程。工作线程不读取或修改地图、Thing、Def数据库、Unity对象和原版全局随机状态；它们只计算矩形、连接点与回溯结果。每个批次完成后固定采用编号最小的成功尝试，因此并发调度不会改变相同地图种子的结果。所有地图登记和格网写入仍在主线程完成。

若正常阶段没有完整结果，才准备紧凑模板池：额外模块固定使用配置下限 24 个，并优先重复占地较小的中转房、小墓室和尽头走廊。紧凑阶段最多 24 次尝试，共享独立的 2400000 次候选预算，不再无限开启下一轮。两阶段合计最多 32 次尝试、2900000 次候选摆放；预算指摆放分支数量，不是毫秒上限或碰撞谓词调用上限。紧凑布局仍使用全部 19 种必选模板、完整接口闭合、一格模块间岩层和 8 格地图边缘。

结构掩码不是简单使用人工地板范围。生成器会先封闭推断出的开放口，再从模板矩形边缘洪泛背景，因此墓室中的粗糙地面、水面和其他天然室内地形仍会被识别为墓葬内部。

## 地图内容

生成顺序如下：

1. 加载并验证全部模板和 metadata。
2. 随机回溯求解完整纵深布局。
3. 全图设置为粗糙砂岩地面和厚岩顶。
4. 生成模板地形、颜色和 Thing，忽略模板屋顶、迷雾与污染。
5. 清理模板捕获时带入的结构外背景。
6. 按房间 XML 即时生成敌人和奖励。
7. 用天然砂岩填满所有非墓葬格。
8. 按原版山地密度和团块尺寸生成钢、机械零件、银、金、铀、塑钢与翡翠矿脉。
9. 在入口走廊尽头放置原版 `CaveExit`。
10. 执行原版迷雾生成步骤。

墓葬使用独立地下生物群系，不运行旧沙坑的蚁群、水域、洞穴生态、野生植物和额外遗迹散布。模板自带的建筑、罐子、石棺、装饰和灯光仍会保留。模板中捕获为玩家派系的建筑在实例化时统一解析为原版敌对古代人阵营 `AncientsHostile`，不会归玩家所有；模板中明确记录的无派系或其他派系保持原语义。

## 房间内容 XML

`1.6/Defs/GiantTomb/Content/NingshaRace_GiantTombRoomContents.xml` 定义五个 `NingshaGiantTombRoomContentDef`，分别负责墓室、大墓室、大厅、储藏室和走廊。`NingshaRace_GiantTombContentCatalog` 汇总五类配置，并在 Def 检查阶段确认布局中的 19 种模板无遗漏、无重复。

主要字段：

- `rooms[].template`：当前敌人表对应的 `ClMapTemplateDef`。
- `rooms[].enemyOutcomes[].weight`：敌人结果相对权重；每个模板实例只抽取一个结果。
- `spawns[].pawnKind/count/factionDef`：普通敌人的种类、数量和阵营。
- `spawns[].permanentMentalState`：可选的永久精神状态；实体阵营生物不配置 `ManhunterPermanent`，避免原版猎杀状态强制敌视同阵营实体。
- `spawns[].mutantDef`：可选的实体转化，侵蚀体使用 `NingshaRace_ErosionBodyMutant`。
- `spawns[].antNestDef/scale`：特殊完整蚁群及其规模倍率，和 `pawnKind` 互斥。
- `rewardPickCount`：当前类别每个房间抽取的资源项数。
- `rewardWithReplacement`：是否有放回；大厅为 `true`，其他类别为 `false`。
- `rewards[].thingDef`：普通奖励来源。
- `rewards[].localStoneBlocks`：从地图世界格自然岩石解析对应石砖，与 `thingDef` 互斥。
- `rewards[].selectionWeight`：资源条目的相对选择权重，省略时为 1。
- `rewards[].quantities[].count/weight`：单项资源的数量档和相对权重。

策划表中的 50、33、25、2 等数值都按相对权重处理，不要求合计为 100。奖励超过 `stackLimit` 时会拆成多堆，并优先分散到不同空格；紧凑房间的独立落点耗尽后，多堆物品可以共享已经选定的奖励格。带品质组件的武器固定为普通品质。生成位置限定在变换后的模板结构掩码内，并排除连接口及相邻格、墙体、建筑、Pawn 和植物。完全没有可用奖励落点或世界格无法解析自然石砖时直接报告模板名或内容 Def。

模板名称映射：

- 策划“地刺召唤物”对应 `NingshaRace_GroundSpikeSummoner`（锐沙方块）。
- 策划“双双通拐角走廊”按实际模板对应 `NingshaRace_GiantTomb_WideTurn`（双通拐角走廊）。
- 策划“走廊”对应 `NingshaRace_GiantTomb_StraightCorridor`（走廊竖）。
- 翡翠铁、敲击兽皮、轻薄皮革和干肉饼分别对应 `Bioferrite`、`Leather_Thrumbo`、`Leather_Light` 和 `Pemmican`。

木乃伊使用 `NingshaRace_GiantTombMummyKind`，基础战力 90、移速 3.2、生命倍率 1.3、主攻击 14。它的利爪使用原版 `ScratchToxic`，毒素会按实际伤害、目标毒素抗性和体型累计；每次造成实际伤害还会累计 0.2 石化严重度，默认五次有效命中达到完全石化。石化增量位于 `NingshaRace_GiantTombMummyCombat.xml`，可直接通过 XML 调整。木乃伊、眼镜蛇和侵蚀体都使用实体阵营，不安装永久猎杀精神状态；唤醒后的进攻由房间 `LordJob_SleepThenAssaultColony` 统一驱动，避免同房间敌人互相攻击。

木乃伊和侵蚀体均归入原版初级异常图鉴与初级异常知识。木乃伊解除迷雾时解锁图鉴，可被收容平台捕获、研究并产出生物铁；侵蚀体继续复用凝砂族原有的收容研究组件，但其 `MutantDef.knowledgeCategory` 与图鉴类别均为 `Basic`。

每个房间生成的木乃伊、眼镜蛇、侵蚀体和墓穴蚁群会按派系加入独立的原版 `LordJob_SleepThenAssaultColony`。生成时它们进入强制睡眠并退出活动 Pawn 索引；玩家打开通路并解除该生物所在格的迷雾时，原版 `Pawn.Notify_Unfogged` 链会唤醒同组威胁。直接伤害休眠者或在附近制造战斗声响也会触发原版唤醒条件。该实现不使用周期扫描，休眠期间不会执行寻敌、巡逻、采集或繁殖工作。

固定南部入口使用 `NingshaRace_GiantTomb_EntranceCorridor` 的单一空威胁结果，不生成木乃伊、眼镜蛇、侵蚀体或蚁群；入口仍按走廊奖励表生成一项奖励。

侵蚀体原身使用不生成关系、武器、意识形态与背景故事的轻量人形请求，但会执行其 `pawnKind` 的服装规则。当前 `NingshaRace_Colonist` 会从带有 `NingshaRaceCompleteOutfit` 标签的凝砂完整套装中随机穿戴一件。石棺尸体继续使用无装备的轻量请求。分帧生成期间只跳过半成品地图自身的 `MapUpdate`，不会把地图临时移出游戏地图表；全局 Pawn 纹理图集回收会暂停到生成结束，从而保持地图索引有效并减少隐藏尸体带来的重复扫描。若生成失败，清理地图前会安排重建运行时 Pawn 图集，避免后续回收阶段访问已经失效的地图索引。

`ErosionBodySpawnUtility` 统一提供未落地生成、地图指定格生成和现有凝砂族转化三个入口。墓葬内容生成和玩家满侵蚀转化都调用该工具；开发者菜单 `NingshaRace / 生成侵蚀体` 可在鼠标空格直接放置一名使用相同规则的侵蚀体。

原版 `EntityCodexEntryDef.PostLoad` 会根据 `uiIconPath` 同时加载正常图标和追加 `_Silhouette` 后缀的未解锁黑影，图鉴未发现时固定绘制后者。木乃伊与侵蚀体都引用原版 `UI/CodexEntries/Shambler`，因此会正常使用原版 `UI/CodexEntries/Shambler_Silhouette`，无需随模组复制重复黑影素材。两者的已解锁图标当前也沿用蹒跚者图标。

## 生成性能

生成管线采用面向发布版本的批处理策略：统一岩顶和墓葬基础地形在新地图首次初始化前直接填充底层网格，不逐格触发绘制、光照和地形事件；全部墓葬 GenStep 共用一次区域与寻路延迟提交，避免模板、内容和外层岩石阶段反复重算全图。天然砂岩利用结构外必为空格的不变量直接登记，跳过重复的可生成与擦除扫描。

布局搜索仍限定为纯数据后台计算。出口首次准备时使用 16 格分桶空间索引，延迟准备的出口只对其创建时的祖先前缀进行永久排除；其余碰撞通过候选失效位图和按房间分组的撤销日志维护。完整房间与连接点仅在进入摆放分支时构造。同批次已有低索引方案成功后，更高索引任务会尽早停止；生成枚举器退出时也会停止并等待全部工作线程收束。后台只读共享几何，实例栈、候选位图、空间索引均由每个求解器独占，地图和实体写入仍在主线程。

生成窗口每帧最多使用约 25 毫秒推进主线程批次，使生成期间仍能刷新进度画面，同时提高总 CPU 利用率。成功生成后日志会输出一条 `[NingshaRace] ...生成用时`，其中包含岩顶、每个 GenStep 和 `FinalizeInit` 的实际耗时，供后续按真机数据继续定位瓶颈。

储藏室2的蚁群结果使用专用 3×3 `NingshaRace_GiantTombAntNest`，不改动 `.clmap`。倍率 1 对应 1 蚁后、4 工蚁、3 兵蚁、常规上限 8、爆浆蚁上限 3 和 12 个实体储藏格。储藏格从敌人与建筑候选中预留，但仍可承载该房间的 XML 奖励；这样不会因为蚁群占位和奖励拆堆重复消耗空间。结算后的规模写入每个 `AntColonyState`，存档、繁殖补员和受击波次都读取本巢数值。墓穴蚁群不生成沙坑蚁穴自带的初始贵重物资；隐藏敌对阵营池会随巢群数量动态扩展。

房间空格使用“列表＋格子索引”的末项交换删除，单次预留不再搬移整段列表；奖励候选列表按房间复用。背景清理仅在目标砂岩、底层地形或涂色不同的情况下调用原版地形更新接口，保留水格、光照和地形事件的原版维护流程。

算法入口、预算语义和静态审查见 [地牢生成算法与性能优化](地牢生成算法与性能优化.md)。本次仅编译和源码检查，未启动游戏或执行性能基准；实际收益以游戏日志为准。

## 封闭砂岩石棺

`NingshaRace_DesertPitSarcophagusLoot` 独立配置石棺内容：固定生成一具 `NingshaRace_Colonist` 古老尸体，所属 `Ancients` 阵营，尸龄 300–350 年；奖励池是墓室资源表的独立副本，每次无放回抽取 1–3 项。

封闭石棺继承原版 `Building_Casket` 流程，使用原版开启指定、右键菜单、寻路、预约、进度条和 `JobDefOf.Open`，不声明重复 JobDef。首次生成时只初始化一次内容并保存状态；打开后先弹出尸体和全部物品，再以相同位置和朝向替换为 `NingshaRace_DesertPitOpenSarcophagus`。该行为同时作用于巨型墓葬、沙漠巨坑和开发者新放置的封闭砂岩石棺。

## 失败策略

以下情况会直接终止生成并清理未完成的口袋地图：

- 模板、metadata 或必需 DLC Def 缺失。
- metadata 版本、尺寸、网格或连接点无效。
- 重复模板分类为空、跨类别重复，或连接点数量不符合分支四接口、尽头一接口、中转房及走廊二接口的要求。
- 连接点总数不能构成使用全部接口的树。
- 模板 Thing 跨越推断出的结构边界。
- 内容目录没有恰好覆盖 19 种模板，或权重、数量、互斥威胁类型和奖励抽取规则无效。
- 房间没有足够空格生成敌人、3×3 蚁穴，或完全没有可容纳物品的奖励落点。
- 当地石材砖、敌人阵营、石棺尸体或开启后建筑无法解析。
- 入口走廊无法容纳原版三乘三出口。

正常阶段预算耗尽后进入一次有独立预算的紧凑阶段；两阶段均未成功时，输出布局 Def、完成尝试数、候选数、碰撞检查数、最深模块数与耗时，并沿用已有失败地图清理链。预算耗尽不代表数学上无解。不会生成半成品墓葬，不回退为旧沙坑，也不无限重试。

## 手工验收清单

下列项目需要在以后启动 RimWorld 时人工确认，本次代码交付不启动游戏：

- 原有 140×140 沙漠巨坑仍可正常进入和返回。
- 新沙漠巨坑恰好生成一个破损石棺；接近提示只发送一次，右键调查会显示进度并替换为开启石棺入口。
- 通过开启石棺入口生成的巨型墓葬尺寸为 200×200，返回出口能够回到同一个沙漠巨坑。
- 19 种模板全部出现，额外模块数量位于 24–32，日志中的普通走廊只占额外二接口模块约四分之一。
- 入口位于南部，主体向北延伸，大墓室位于较深支路。
- 所有模块连通且没有悬空开放口或两格连续门。
- 非墓葬区域全部是砂岩或允许的七种矿物。
- 全图屋顶均为厚岩顶。
- 旋转、镜像后墙体、门和建筑朝向正确。
- 模板墙体、门、石棺和其他可拥有派系的建筑属于敌对古代人而非玩家，且模板无派系物体没有被错误分配派系。
- 返回出口能够回到生成该地图的地表入口。
- 除入口外的 18 种模板各自敌人结果与策划表一致，重复模板实例沿用相同表但独立抽取；固定南部入口始终没有怪物。
